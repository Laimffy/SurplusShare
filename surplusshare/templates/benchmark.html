Theoretical Complexity Analysis & Academic Findings

Merge Sort
O(n log n)

Merge Sort guarantees $O(n \log n)$ comparisons regardless of initial order. Auxiliary space is $O(n)$ due to merge buffer sublists. The stability of Merge Sort ensures that food listings posted earlier maintain precedence when expiry timestamps coincide.

Linear Search
O(n)

Linear Search checks every entry sequentially. For a single one-off query ($Q = 1$), it avoids the $O(n \log n)$ sorting overhead. However, when evaluating multiple queries, total work grows linearly as $O(Q \cdot n)$.

Binary Range Query
O(log n + k)

Lower and upper bounds are found in $O(\log n)$ comparisons each. Once boundaries are established, the engine scans the $k$ matching records inside the window. For large workloads ($Q \gg 1$), Binary Search significantly outperforms Linear Search.

Amortized Analysis & Break-Even Equation

Sorting has an initial cost $T_{sort}$. Each subsequent binary search query costs $T_{binary}$, whereas each linear query costs $T_{linear}$. The break-even query count $Q_{break-even}$ is given by:
Q ≥ T_sort / (T_linear - T_binary).
Whenever the system expects to perform more than $Q_{break-even}$ queries during a donation cycle, pre-sorting listings with Merge Sort is strictly more efficient.
